# 01. Domain Layer (`Taxi.Domain`) Exhaustive Analysis

The Domain layer implements the core business logic, adhering strictly to Domain-Driven Design (DDD) principles. It has zero external dependencies (no Entity Framework, no third-party SDKs) and uses a robust `Result<T>` pattern instead of exceptions for business rule violations.

## 1. Core Abstractions & Primitives

### `Entity` & `AuditableEntity`
- **`Entity`**: The base class for all aggregates. Provides a unique `Guid Id` (generated if empty) and a private list of `DomainEvent` objects (which inherit from MediatR's `INotification`). Methods include `AddDomainEvent`, `RemoveDomainEvent`, and `ClearDomainEvents`.
- **`AuditableEntity`**: Inherits from `Entity` and adds `CreatedAtUtc`, `CreatedBy`, `LastModifiedUtc`, and `LastModifiedBy`. These fields are populated automatically by an EF Core interceptor in the Infrastructure layer, never manually.

### `ValueObject`
- Implements value equality by overriding `Equals`, `GetHashCode`, `==`, and `!=`. Derived classes must implement `GetEqualityComponents()`.

### `LocalizedText` (Critical Value Object)
- Represents a multilingual string stored as a single `JSONB` column in PostgreSQL.
- Supports exactly 9 languages: English (`En`), Arabic (`Ar`), Dutch (`Nl`), German (`De`), Polish (`Pl`), Ukrainian (`Uk`), French (`Fr`), Spanish (`Es`), Romanian (`Ro`).
- Contains a `GetTranslation(string languageCode)` method with fallback to English. 

### `Result<T>` & `Error`
- Exceptions are strictly banned for business logic. Every mutating method returns `Result<T>` or `Result<Success>`.
- **`Error`**: A readonly record struct containing:
  - `Code`: Mapped to a localization key (e.g., `LocalizationKeys.Auth.UserNotFound`).
  - `Description`: English fallback text.
  - `Type` (`ErrorKind`): Maps to HTTP statuses via pipeline behaviors. (`Failure`, `Unexpected`, `Validation`, `Conflict`, `NotFound`, `Unauthorized`, `Forbidden`).
  - `PropertyName`: Used for FluentValidation property mapping.

## 2. Aggregates and Entities

### Users & Identity (`User`, `RefreshToken`)
- **`User`**: Tracks `Passenger`, `Driver`, or `Admin` roles (`UserRole` enum).
  - Contains `LocalizedText Name`, `Phone`, `Email`, and `FcmToken`.
  - Methods: `Create()`, `Deactivate()`, `Activate()`, `SoftDelete()`, `UpdateProfile()`, `AssignVehicle()`, `UnassignVehicle()`, `UpdateFcmToken()`.
- **`RefreshToken`**: Stores long-lived JWT refresh tokens globally (`Token`, `UserId`, `ExpiresOnUtc`).
- **Errors**: `AuthErrors` (Name validation, Phone mismatch, Firebase token errors).

### Drivers & Vehicles (`Driver`, `Vehicle`, `VehicleType`)
- **`Driver`**: Extends `AuditableEntity`. Tracks a specific driver's performance and state.
  - State: `LicenseNumber`, `ActiveVehicleId`, `AcceptanceRate` (default 1.0), `CompletionRate` (default 1.0), `TotalTripsCompleted`, `IsActive`.
  - Real-time: `CurrentLat`, `CurrentLng`, `LocationUpdatedAt`.
  - `DriverStatus`: `Offline`, `Online`, `OnTrip`, `Blocked`.
- **`VehicleType`**: Configuration entity defining pricing logic.
  - State: `Code`, `LocalizedText Name`, `PassengerCapacity`, `RatePerKm`, `RatePerMin`, `MinimumFare`, `CurrencyCode`, `SortOrder`.
- **`Vehicle`**: Binds a `Driver` to a `VehicleType` along with physical car details (`Make`, `Model`, `Year`, `Color`, `LicensePlate`).

### Trips (`Trip`, `PricingQuote`, `TripRoute`, `TripStop`)
- **`PricingQuote`**: An immutable snapshot of trip pricing generated *before* a trip is requested.
  - Fields: `TotalDistanceKm`, `TotalDurationMin`, `FinalFare`, `OriginalFare`, `DiscountPercent`, `ValidUntil` (usually 15 mins).
  - Validation: Prevents negative distances and negative fares.
- **`Trip`**: The central state machine of the business.
  - **`TripStatus`**: `PendingQuote`, `Scheduled`, `PendingDriver`, `DriverAssigned`, `InProgress`, `Completed`, `Cancelled`, `AwaitingPayment`, `PaymentFailed`, `Refunded`.
  - **Methods & Transitions**:
    - `Request()`: Validates quote expiry, requires >= 2 stops. Transitions to `AwaitingPayment`.
    - `ConfirmPayment()`: Transitions to `Scheduled` or `PendingDriver`.
    - `AssignDriver()`: Transitions to `DriverAssigned`.
    - `Start()`: Transitions to `InProgress`.
    - `Complete()`: Transitions to `Completed`.
    - `Cancel()`: Cannot cancel if completed or refunded.
  - Note: Every single state transition generates a respective Domain Event.
- **`TripRoute`**: Holds the `EncodedPolyline` generated by Google Maps, bounding it to a `TripId`.
- **`TripStop`**: A local record struct (`Coordinate`, `Sequence`, `AddressLabel`).

### Payments & Billing (`Payment`, `PassengerPaymentMethod`, `PromoCode`)
- **`Payment`**: Strongly tied to Stripe.
  - State: `Amount`, `Currency`, `Method` (`Cash`, `CreditCard`, `Wallet`), `Status` (`Pending`, `Completed`, `Failed`, `Refunded`).
  - Stripe Fields: `StripePaymentIntentId`, `StripeClientSecret`, `StripeChargeId`.
- **`PassengerPaymentMethod`**: Stores vaulted credit cards (`GatewayPaymentMethodId`, `LastFour`, `CardBrand`) for fast checkout.
- **`PromoCode`**: Manages discounts (`DiscountAmount`, `DiscountPercentage`), `ExpiresAtUtc`, and `MaxUsageCount`. Method `IsValid()` guarantees time and count constraints.

### Audit & Config (`AuditLog`, `AppConfig`)
- **`AuditLog`**: Formal tracking entity (`Action`, `EntityName`, `EntityId`, `OldValue`, `NewValue`, `UserId`).
- **`AppConfig`**: Dynamic system settings (`Key`, `Value`, `Description`), e.g., `AppConfigKeys.TripDiscountPercent`.

## 3. Domain Events

Events are fired whenever a mutation occurs on an aggregate. They are heavily utilized by the `Trip` entity to decouple side effects (like sending SignalR sockets or Push Notifications) from database transactions.

- **`TripRequested`**: Fired when a passenger initially locks in a trip.
- **`PaymentConfirmed`**: Fired when a Stripe Webhook succeeds. Triggers the actual driver dispatch process.
- **`PaymentFailed`**: Carries a `Reason`. Fired if Stripe rejects the card.
- **`DriverAssigned`**: Fired when an admin/system links a driver to a trip. Notifies the passenger.
- **`TripStarted`** & **`TripCompleted`**: Triggers state updates for the connected clients.
- **`TripCancelled`** & **`TripRefunded`**: Notifies users and potentially triggers Stripe refund commands in the Application layer.

## 4. Exception Handling vs. Errors

The Domain layer throws zero exceptions. Instead, it relies on static error classes (e.g., `AuthErrors.cs`, `TripErrors.cs`). 
Example error signature:
```csharp
public static readonly Error QuoteExpired = Error.Validation(
    code: LocalizationKeys.Trip.QuoteExpired,
    description: "The quote has expired. Please request a new one.");
```
This forces all caller code (in the Application layer) to pattern-match on `Result.IsSuccess` or return the `Error` back through the HTTP pipeline, ensuring flawless, predictable execution.
